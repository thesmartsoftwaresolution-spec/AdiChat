verified 1. Optimistic Concurrency Control (OCC)

Assumes transaction conflicts are rare. Operations proceed without locks and only validate integrity before commit.

  • Best for: High-read, low-write transactional systems.
  • Mechanism: Relies on record versioning or epoch timestamps.

WHERE id = 42 AND version = 1;

lock 2. Pessimistic Locking

Assumes collisions are inevitable. Explicitly reserves records via exclusive row-level or table locks beforehand.

  • Best for: High contention data sets (e.g., flight booking, inventory decrement).
  • Tradeoff: Guarantees strict isolation but risks deadlocks and queue latency.
